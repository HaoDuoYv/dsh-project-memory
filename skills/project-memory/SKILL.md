# 项目记忆（DSH）

记忆的价值**不是复述代码**。改了哪些文件 git log 已经记了，代码本身也读得到。
记忆只该存**读代码看不出来的东西**：为什么这么做、下次别踩什么、这个约束是谁定的。

判断一条内容该不该写，只问一句：**「下个月还成立吗，而且光看代码能看出来吗？」**
两个都是「是」才写。

## 何时触发

一次会话里出现下面任意一种，就在**交付回答之前**处理记忆：

- 改了代码 / 配置 / 部署方式，且行为或约束发生了变化
- 修了 bug —— 尤其是**定位过程反直觉**的那个（症状指向 A，根因在 B）
- 做了选型并给出理由（换框架、换格式、砍掉某个功能）
- 用户表达了偏好、约定、或"以后都这么干"
- 发现环境 / 工具链的坑（端口会变、某命令被安全阀拦、编码会把文件写坏）

不触发：问候、查资料、一次性问答、读个文件给个结论。

## DSH 收尾守卫（硬保证）

本机装了本包的收尾守卫（两种实现，规则一致，都不要绕过）：
**原生插件**（`agent/turn-stopping`）或 **Claude Code 风格钩子桥**（`Stop` 钩子）。
**本会话动过手（改过文件，或跑过 ≥2 条命令）却没写记忆时，收尾会被拦截一次**，
拦截理由以一条中文消息进入你的下一轮上下文，补写记忆后才能正常结束。

也就是说：收尾不写记忆会被强制再跑一轮 —— 不要等被拦，主动先写。
真的无可沉淀（纯查证、纯答疑）时，明确说一句「无需记录」+ 一句理由，守卫不会二次拦截同一周期。

守卫的实现细节（拦截上限、状态目录、两条路线别同时装）见仓库 README；写记忆时你只需要知道规则。

## 四个落点

| 文件 | 存什么 | 形态 |
|---|---|---|
| `<project>/.dsh/memory/YYYY-MM-DD.md` | 当天做了什么、为什么、踩了什么坑 | 首行 `# YYYY-MM-DD`，下接 `## 主题`，必要时 `### 子节` |
| `<project>/.dsh/memory/MEMORY.md` | 长期成立的**铁律**（架构硬规则、禁做事项、数据格式约定） | 见下「长期记忆的两份文件」 |
| `<project>/.dsh/memory/PLAYBOOK.md` | **某类操作怎么做**（部署 / 推送 / 实机调试 / 打包） | 见下「长期记忆的两份文件」 |
| `~/.dsh/user-memory/MEMORY.md` | 跨项目的个人偏好与习惯 | 少量条目，手工维护 |

路由口诀：

- **「某天发生了什么」→ 当日日志**
- **「这个项目永远得遵守」→ MEMORY.md**
- **「再做一次这个动作要注意什么」→ PLAYBOOK.md**
- **「跟我这个人有关，跟哪个仓库无关」→ 用户级**

同一条内容常常**两边都要**：当日日志记经过（含会过期的端口、路径、报错原文），
MEMORY.md 只留提炼后的那句规则。日志负责"当时到底怎么回事"，MEMORY 负责"以后怎么干"。

## 长期记忆的两份文件

真实项目的长期记忆长这样（照 `E:\study\gitproject\zhilu\.workbuddy\memory` 的产物写，
迁移后同一份内容在 `<项目>/.dsh/memory`）。**两份都要有头、都要分区、头部互相指路。**

### MEMORY.md —— 写代码时的手铐

````markdown
# <项目名> 长期记忆

<一两句项目身份：技术栈 / 包名 / 关键目录 / 设计文档位置>
**<操作类事项> 的操作手册与踩坑全集见同目录 `PLAYBOOK.md`，动这些前先读。**

## 构建与验收
## 架构硬规则
## 单元测试
## 待查
````

- 每条 bullet 的骨架：**`- **铁律**：具体标识符 + 为什么 + （日期）+ 「别再…」`**
  - 具体标识符 = 文件 / 类 / 方法 / 常量 / 表名 / 枚举值。写「配色走 md3 语义 token」没用，
    要写「色值在 `ui/theme/ThemePalettes.kt`、存储只放名字、新色追加枚举末尾」
  - 定下或改掉的规则带日期：`通用交互件已全部收口双态 wrapper（2026-10-11）`
  - 走过回头路的写一句「**别再回到 …**」，并说清为什么不 —— 这条挡住的是"看起来更简洁"的倒退
- 分区按**出事面**，不按文件：构建与验收 / 架构硬规则 / 单元测试 / 待查
- `## 待查` 放悬而未决的现象（一行一个），解决后**删掉**，不要留着当历史
- 水位：本机真实样本约 **10KB / 56 行**。逼近就合并同主题条目 —— 它是规则清单，不是流水账

### PLAYBOOK.md —— 执行某个动作前的核对单

````markdown
# <项目> 开发操作手册（MEMORY.md 的展开版）

> MEMORY.md 只留「写代码必须遵守的铁律」；本文件放「怎么做」的完整操作与踩坑全集。
> 动 <高风险动作> 前，先来这里对照。

## GitHub 推送
## 实机 / 模拟器测试
## Release 打包
## 本地调试 <某服务>
````

- 分区按**操作域**（推送 / 实机测试 / 打包 / 本地调试…），一个域一节
- 每条必须是**能直接复制去跑的命令**，或**原样贴出的报错串**，或**会变的值怎么现场取**
  （代理端口、设备序列号、模拟器坐标空间 —— 写死的历史值要标"曾 16384，会变"）
- 禁做项单独强调：「**绝不 `svc wifi disable` 造断网**（会连 adb 一起打掉）」
- 与 MEMORY.md 的分工：MEMORY 是「写代码时的手铐」，PLAYBOOK 是「动手前的手册」；
  MEMORY 里放不下的执行细节全部下推到 PLAYBOOK，两处头部互相指路

## 项目根怎么定（与 DSH 自己的规则一致）

从会话工作目录（`cwd`）逐级向上找 `.git`，**找到就用那一级**；一路到盘根都没有 `.git`，
就用 cwd 本身。记忆落在 `<项目根>/.dsh/memory/`。

坑：`~/.dsh` 是 DSH 自己的 home（技能、会话、插件都在里面），**它不算项目根**。
所以本文的根判定只看 `.git`，不看 `.dsh` 是否存在 —— 否则在主目录下开会话会写进 DSH 自己的目录。

## 写什么 / 不写什么

写：

- **结论 + 理由**，不只写动作。"砍掉 HTML 块渲染，因为与双主题、文本选择、单测体系全面冲突"，后半句才是价值。
- **症状 → 根因 → 修法**。症状要写成**别人搜得到的样子**：把真实报错串、日志行**原样**贴进去
  （`SQLITE_READONLY`、`Could not find any Python installation`），这是将来唯一的检索锚点。
- **反直觉的因果**："改了 A 却导致 B"，"看起来是 X 其实是 Y"。
- **边界与例外**：什么情况下这条规则不成立。

不写：

- 文件清单（`git log` 有）、代码片段（仓库有）
- 临时路径、中间产物、一次性的工具报错、失败的尝试本身
- 任何密钥（见下）
- 长篇散文。记忆是给人**扫**的，不是给人读的

## 格式

当日日志的真实形态：一天一个文件，首行日期，下面按主题分块，块内一个 bullet 一件事。

````markdown
# 2026-10-17

## 可选云端服务（账号 + 用户中心 + 手动云端备份）

<两三句：用户要什么、关键决策是什么、为什么这么选>

### 服务端 `server/`

- 单容器 + 单数据卷（`/data` = `app.db` + `avatars/` + `backups/`）
- 安全上做的：bcrypt(10)、验证码只存 sha256、JWT HS256 + 每次请求回查用户
- 没做（写在 README）：JWT 无法吊销、SQLite 单机

### App 侧

- **明文 HTTP 必须显式放行**：新增 `res/xml/network_security_config.xml`
````

要点：

- **`## 标题` 一句话说清是什么事**；同一天多件事就多个 `##`，再大就拆 `###`
- 块首给两三句背景（需求是什么、选了什么），然后才是 bullet
- bullet 里出现过的报错串、命令、路径都**原样**留，这是将来的检索锚点
- `append_memory.py` 追加时写的就是 `## <标题>`（新建当天文件会自动补 `# <日期>` 首行）

## 四条硬约束

1. **只追加，不覆盖。** 当日日志是累加文件。用 `>>` 或 Edit，**永远不要**用会重写整文件的写入方式 ——
   一次误覆盖就把几十条历史抹了。
2. **不写密钥。** `JWT_SECRET`、SMTP 授权码、令牌、密码，一律只记「配置在哪个文件的哪个键」，
   不记值。用户把密钥发给你了也一样 —— 记"已配置 QQ 邮箱 SMTP"就够了。
3. **不重复。** 写之前先 `grep` 目标文件；同一事实已存在就地更新（带日期），不要再追加一条。
4. **记忆不是交付物。** 先把活干完、把结论回答给用户，记忆是补充动作。
   绝不能用「已写入记忆」代替真正的回答。

## 用脚本追加（推荐）

`scripts/append_memory.py` 把上面三条护栏做成了硬检查：只追加、拒绝疑似密钥、同名标题不重复追加。
脚本不依赖 DSH 在跑，纯 Python 3 标准库。

```bash
# 当日日志（自动取日期）
echo "- 结论：..." | python scripts/append_memory.py --title "修 Docker 构建失败"

# 长期规则
python scripts/append_memory.py --title "备份只有 .dtk 一种格式" --file memory < note.md

# 操作手册
python scripts/append_memory.py --title "上 HTTPS" --file playbook < note.md

# 指定项目根（默认从当前目录往上找 .git，没有就用当前目录）
python scripts/append_memory.py --root E:/study/gitproject/zhilu --title "..." < note.md

# 先看看会写成什么样
python scripts/append_memory.py --title "..." --dry-run < note.md
```

退出码：`0` 成功或已存在、`2` 命中疑似密钥（指出命中的键名，不回显值）、`1` 其它错误。

用户级（`~/.dsh/user-memory/MEMORY.md`）不归脚本管 —— 那是单个文件的少量条目，手工追加即可。

## 收尾

记忆写完，用一句话告诉用户记在哪个文件了（"已记到 `MEMORY.md`"），
不要把记忆内容再复述一遍 —— 他刚跟你一起经历了这件事。

## 归档（蒸馏）

当日日志超过 30 天就蒸馏，动作是**搬 + 提 + 删**，不是复制：

1. **提**：按主题把可长期成立的部分提炼成规则，一条一句话
2. **搬**：规则进 `MEMORY.md` 的对应分区；属于"怎么做"的执行细节进 `PLAYBOOK.md` 的对应操作域
3. **并**：目标文件里已有同主题条目就地合并（带日期），不要新开一条平行条目
4. **删**：确认提炼完再删旧日志文件

`MEMORY.md` 逼近 ~10KB 时同样先合并同主题条目 —— 它该是规则清单，不是流水账。
日志里那些**只属于那一天**的东西（端口、报错原文、试错过程）就随文件一起消失，不要搬进长期文件。

更多「好条目 vs 坏条目」的对照见 `references/examples.md`。

## DSH 侧的坑

- **技能发现只有一层**：`~/.dsh/skills/<name>/SKILL.md`（目录 bundle）或 `~/.dsh/skills/<name>.md`；
  不支持嵌套 `**/SKILL.md`；`name` 必须 kebab-case，否则整条被静默丢弃。
- **改正文立即生效**；改 frontmatter 或增删技能目录要等下一步模型请求刷新；
  改 `profiles/desktop/cordis.patch.yml` 必须**重启 DSH**（桌面 profile 只能由 Electron 应用管理）。
- **`Stop` 是唯一可用的收尾挂点**：DSH 的钩子桥不支持 Claude Code 的 `SessionEnd`
  （支持集只有 `SessionStart`/`UserPromptSubmit`/`PreToolUse`/`PostToolUse`/`Stop`/`SubagentStart`/`SubagentStop`）。
- **守卫必须自限次**：桥里 `stop_hook_active` 恒为 `false`，也没有连击上限，一个无条件阻塞的 `Stop` 钩子会无限续轮 ——
  `memory_guard.py` 用「每个工作周期最多拦一次 + 全会话硬上限」的状态文件兜住这一点。
